# 배포 안내

## 정적 서버에 배포

1. `dist/`의 내용을 회사 서버의 웹 루트에 복사합니다.
2. `/`, `/stores`, `/guide`를 각각 열고 직접 새로고침합니다.
3. 도메인과 HTTPS 인증서를 회사 운영 절차에 따라 연결합니다.
4. 최종 도메인이 결정되면 세 HTML 원본의 `og:image`를 `https://실제도메인/assets/social.png` 형식으로 변경하고, 해당 페이지의 canonical 및 `og:url`을 추가한 후 다시 빌드합니다. 임의의 회사 도메인은 넣지 않았습니다.

이미지·글꼴·코드는 모두 같은 서버에서 제공합니다. 페이지 표시에는 Figma/CDN 접속이나 Figma 구독이 필요하지 않습니다. 외부 주문·채팅 링크를 열 때는 해당 서비스 접속이 필요합니다.

이 배포본은 도메인 루트(`/`) 기준입니다. `/brand/` 같은 하위 경로 배포가 필요하면 빌드 base, 페이지 링크, 이미지 경로를 함께 바꾸고 재검증해야 합니다.

## Nginx 예시

`root`는 회사 서버의 실제 경로로 바꿉니다. 아래는 기존 HTTPS 가상호스트 안에 넣을 경로 설정 예시이며 인증서·도메인 설정은 포함하지 않습니다.

```nginx
root /var/www/manmanmarket/dist;
index index.html;
location = /stores { try_files /stores/index.html =404; }
location = /guide { try_files /guide/index.html =404; }
location / { try_files $uri $uri/ =404; }
```

`/stores/`, `/guide/` 디렉터리의 index.html을 제공하는 일반 웹서버에서도 동작합니다. 정적 호스팅 서비스에서는 빌드 명령을 `npm run build`, 배포 폴더를 `dist`로 지정합니다.

회사 호스팅이 HTML 파일 업로드만 지원해도 빌드된 `dist/`를 사용할 수 있습니다. 반면 Cafe24 **쇼핑몰 스킨 편집창**에 React 소스 전체를 붙여 넣는 방식은 이 전달본의 배포 방식이 아닙니다.

## 배포 전 회사 확인 항목

- 수지 신봉점 카카오톡 URL 및 신규 3개 지점 상세 주소·지역 정보 입력 여부. 미입력 상태에서도 ‘준비 중’ 표시로 동작합니다.
- 최종 도메인, HTTPS, 공유 이미지의 절대 주소 및 검색 노출 정책.
- 각 지점의 실제 로그인·주문 동선과 휴대전화 카카오톡 앱 연결. 이 작업에서는 로그인·주문·방 참여를 실행하지 않았습니다.
- 기존 Figma 원본 주석에 남아 있던 언론사 사진 및 후기 재사용 확인 사항. 출처는 `assets-manifest.json`, 원본 코드와 `콘텐츠-출처.md`에 보존했습니다.

기존 Figma 사이트를 수정하거나 다시 게시하지 않았습니다. 이 자료는 회사의 별도 배포용입니다.
